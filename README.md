# Leaf Image Processing

A single-notebook Digital Image Processing course project on apple leaf images
from PlantVillage. Active pipeline: **denoising -> Sobel and Canny -> GLCM**.

## Repository Structure

```text
DIP_Project/
  README.md
  requirements.txt
  Comentarios_Ferrari.txt
  notebooks/
    apple_leaf_analysis.ipynb  # All configuration, functions, analysis and figures
  data/
    samples/                  # Four demonstration images and their provenance
    raw/                      # Full apple subset; not processed automatically
  outputs/
    glcm.csv                  # Detailed GLCM results generated by the notebook
    glcm_summary.csv          # Per-class GLCM summary generated by the notebook
```

All active analysis is inside
[`apple_leaf_analysis.ipynb`](notebooks/apple_leaf_analysis.ipynb).
There is no dependency on a local `leaf_analysis` package or on ImageJ.
Functions are grouped near the beginning: denoising filters, edge detectors,
GLCM operations and presentation. Each filter has its own function.

`local/`, `.venv/` and editor settings remain local-only and ignored by Git.
Superseded notebooks, helper modules, tests and outputs were moved under
`local/archive/repository_cleanup_2026-09-22/` to preserve earlier work without
keeping it in the active project. The notebook neither reads nor executes them.
`local/review.md` is only updated upon an explicit request.

## Setup and Execution

Use Python 3.10 and the Python/Jupyter extensions in VS Code.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

On Windows, create the environment with `py -3.10 -m venv .venv` and activate
it with `.venv\Scripts\Activate.ps1` in PowerShell (not verified on Windows).

1. Open the project folder and the main notebook.
2. Select the Python interpreter inside `.venv`.
3. Restart the kernel and run the notebook from top to bottom.
4. Save the notebook to retain its figures and tables.

For a terminal execution on Linux, update the same notebook instead of creating
copies in `outputs/`:

```bash
.venv/bin/python -m jupyter nbconvert --to notebook --execute --inplace notebooks/apple_leaf_analysis.ipynb
```

The last GLCM cell creates or overwrites only `outputs/glcm.csv` and
`outputs/glcm_summary.csv`. Figures stay in the main notebook. No executed
notebooks, historical tuning tables or ImageJ artifacts are generated there.

## Workflow and Configuration

1. Load one image per class and the embedded tuning snapshot.
2. Compare median, bilateral and Gaussian denoising.
3. Select the denoising output and apply Sobel and Canny independently.
4. Apply GLCM to the configured grayscale ROIs of the selected denoised images.

GLCM is presented after the edges but uses grayscale intensity, not Canny's
binary map. The workflow ends there: no segmentation, LBP, FFT, classifier,
threshold comparison or stability experiment.

The setup cell contains the filter selection, Gaussian parameters, Canny
thresholds, ROI coordinates and GLCM levels/distances/angles.
`MOSTRAR_HISTORICOS=False` leaves the separate NLM/BM3D functions available
without executing these optional historical comparisons.

## Interpretation Limits

- The frozen tuning snapshot is dated 2026-09-21 16:39 UTC. Sigmas 5 and 10 are
  complete, 15 is partial, and the default is 10. No search is rerun.
- MSE/PSNR/SSIM are historical tuning results, not quality scores of the four
  demonstration photos. Gaussian parameters are manual.
- The 64x64 ROIs are exploratory, not annotated lesions. Their GLCM properties
  do not establish a best filter or diagnose disease.
- Sobel/Canny show image transitions, not validated lesion segmentations.
- Four examples do not establish performance on the complete dataset.

## Images and Dataset

The repository includes the **complete apple subset**, both unaugmented and
augmented versions, so cloning also downloads the data for future experiments.
The notebook still processes only the four selected images in `data/samples/`
(about 56 KB), which are unmodified copies of files in `data/raw/without/`.
The small copies make the current demonstration's inputs explicit and stable.

The complete dataset contains approximately 111 MiB of image data. These are
ordinary Git files, so Git LFS is not required. Avoid repeatedly replacing image
binaries: Git history retains old versions and can grow over time.

The [sample notes](data/samples/README.md) include filenames, provenance details,
checksums and download instructions. A reference distribution is available from
[Mendeley Data, version 1](https://data.mendeley.com/datasets/tywbtsjrjv/1),
DOI `10.17632/tywbtsjrjv.1`. No separate download is required after cloning this
repository. To obtain an independent copy from the source, download the **without
augmentation** archive and keep all images in the four `Apple___*` directories
under `data/raw/without/`; use `data/raw/with/` for the augmented archive.
The current notebook reads only `data/samples/`; the larger dataset does not
trigger a batch run.

The original local workspace already contains the full apple class counts below.
These files were preserved during reorganization, so no second download was
needed on the author's computer. A fresh clone includes both apple subsets.

| Apple scab | 630 | 1,000 |

| Cedar apple rust | 275 | 1,000 |

These are local file counts, not a checksum verification against the downloaded
