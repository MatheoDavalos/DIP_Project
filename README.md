# Leaf Image Processing

Course project by Juliano Eleno Silva Pádua and Matheo Sebastian Duarte Davalos.

A single-notebook Digital Image Processing course project on apple leaf images
from PlantVillage. Active pipeline: **denoising -> Sobel and Canny -> GLCM**.

## Repository Structure

```text
DIP_Project/
  README.md
  requirements.txt
  LICENSE                     # MIT license for original code
  scripts/
    download_data.py           # Optional dataset download and SHA-256 verification
  notebooks/
    apple_leaf_analysis.ipynb  # All configuration, functions, analysis and figures
  data/
    samples/                  # Four demonstration images and their provenance
    download_manifest.json    # Pinned source, file sizes and SHA-256 checksums
    raw/                      # Optional download; ignored by Git
  outputs/
    glcm.csv                  # Detailed GLCM results generated by the notebook
    glcm_summary.csv          # Per-class GLCM summary generated by the notebook
```

All active analysis is inside
[`apple_leaf_analysis.ipynb`](notebooks/apple_leaf_analysis.ipynb).
There is no dependency on a local `leaf_analysis` package or on ImageJ.
Functions are grouped near the beginning: denoising filters, edge detectors,
GLCM operations and presentation. Each filter has its own function.

## Setup and Execution

Use Python 3.10 and the Python/Jupyter extensions in VS Code.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

On Windows, create the environment with `py -3.10 -m venv .venv` and activate
it with `.venv\Scripts\Activate.ps1` in PowerShell (not verified on Windows).

1. Open the project folder and the main notebook.
2. Select the Python interpreter inside `.venv`.
3. Restart the kernel and run the notebook from top to bottom.
4. Save the notebook to retain its figures and tables.

For a terminal execution on Linux, update the same notebook instead of creating
copies in `outputs/`:

```bash
.venv/bin/python -m jupyter nbconvert --to notebook --execute --inplace notebooks/apple_leaf_analysis.ipynb
```

The last GLCM cell creates or overwrites only `outputs/glcm.csv` and
`outputs/glcm_summary.csv`. Figures stay in the main notebook. No executed
notebooks, historical tuning tables or ImageJ artifacts are generated there.

## Workflow and Configuration

1. Load one image per class and the embedded tuning snapshot.
2. Compare median, bilateral and Gaussian denoising.
3. Select the denoising output and apply Sobel and Canny independently.
4. Apply GLCM to the configured grayscale ROIs of the selected denoised images.

GLCM is presented after the edges but uses grayscale intensity, not Canny's
binary map. The workflow ends there: no segmentation, LBP, FFT, classifier,
threshold comparison or stability experiment.

The setup cell contains the filter selection, Gaussian parameters, Canny
thresholds, ROI coordinates and GLCM levels/distances/angles.
`MOSTRAR_HISTORICOS=False` leaves the separate NLM/BM3D functions available
without executing these optional historical comparisons.

## Interpretation Limits

- The frozen tuning snapshot is dated 2026-09-21 16:39 UTC. Sigmas 5 and 10 are
  complete, 15 is partial, and the default is 10. No search is rerun.
- MSE/PSNR/SSIM are historical tuning results, not quality scores of the four
  demonstration photos. Gaussian parameters are manual.
- The 64x64 ROIs are exploratory, not annotated lesions. Their GLCM properties
  do not establish a best filter or diagnose disease.
- Sobel/Canny show image transitions, not validated lesion segmentations.
- Four examples do not establish performance on the complete dataset.

## Exploratory GLCM Results

The committed [summary CSV](outputs/glcm_summary.csv) contains the following
values (rounded to four decimals). Each row represents **one image and one
manually selected 64×64 ROI**, with 32 gray levels. Descriptors are averaged over
12 distance/angle combinations: distances 1, 2 and 4 pixels; angles 0°, 45°, 90°
and 135°. These are not averages over multiple images per class.

| Example class (n = 1 each) | Contrast | Dissimilarity | Homogeneity | Energy | ASM | Correlation |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Apple scab | 3.0042 | 1.0032 | 0.6471 | 0.2450 | 0.0602 | 0.6416 |
| Black rot | 29.7860 | 3.7955 | 0.2986 | 0.0761 | 0.0058 | 0.7531 |
| Cedar apple rust | 0.5107 | 0.3568 | 0.8367 | 0.2862 | 0.0827 | 0.9188 |
| Healthy | 2.8014 | 0.9490 | 0.6632 | 0.2240 | 0.0503 | 0.6653 |

For these particular ROIs, black rot has the highest contrast (29.7860), while
cedar apple rust has the highest homogeneity (0.8367). These observations describe
selected regions; they do not establish disease-specific signatures, diagnostic
accuracy or generalization. There is no trained classifier or held-out evaluation.
The [detailed CSV](outputs/glcm.csv) provides all 48 descriptor rows. Run the
notebook to regenerate both CSVs; update this table if the configuration changes.

## Images and Dataset

Only the **four demonstration images** in `data/samples/` (about 56 KB) are
versioned as dataset inputs. They are sufficient to run the notebook. The
[sample notes](data/samples/README.md) document their provenance and SHA-256
checksums. The optional full dataset is stored in `data/raw/`, ignored by Git,
and does not trigger a batch analysis.

To restore the unaugmented apple subset using Python's standard library:

```bash
python scripts/download_data.py
python scripts/download_data.py --verify-only
```

Use `--subset with` for augmented images or `--subset all` for both subsets.
The script downloads a ZIP of the repository's pinned historical snapshot and
extracts only the requested images after verifying their sizes and SHA-256 hashes
against [the manifest](data/download_manifest.json). The ZIP includes both
subsets even when only one is selected. Already valid local images are reused.
Use `--archive /path/to/snapshot.zip` to reuse a downloaded ZIP offline.

| Apple class | Without augmentation | With augmentation |
| --- | ---: | ---: |
| Healthy | 1,645 | 1,645 |
| Apple scab | 630 | 1,000 |
| Black rot | 621 | 1,000 |
| Cedar apple rust | 275 | 1,000 |
| **Total** | **3,171** | **4,645** |

These counts and checksums identify the project's preserved dataset, not an
independently verified copy of the upstream Mendeley archives. The reference
source is [Mendeley Data, version 1](https://data.mendeley.com/datasets/tywbtsjrjv/1),
DOI `10.17632/tywbtsjrjv.1`.

Approximately 111 MiB of images remain in earlier Git commits. Removing them
from the current tree prevents further routine tracking but does **not** shrink
existing history or normal full clones. A shallow clone (`git clone --depth 1`)
after this cleanup is committed avoids downloading the old dataset history.
The download script relies on that pinned historical commit remaining available;
any future history rewrite must first migrate the download to a durable data host
and update the manifest. Define data splits before generating augmented variants.
